Task 011 · wireframes · stacked on 010 (PR #441)

Exporter deep-link fallback — paste the link by hand

010 made every upload enter through a cadernin-export:// link and dead-ended the exporter when there was none. Wireframes keep that rule — there is still no unscoped upload — but the authenticated area gains an escape hatch: the same link, copied on the website and pasted by hand, resolves the same destination a protocol launch would. The existing link format stays unchanged: cadernin-export://upload?projectId=…&….

Both entry points («Enviar partitura» on the project page, «Enviar nova versão» on the songbook-scoped score page) are already anchors carrying the deep link as their href. The fallback only teaches the copy gesture; the website ships no new control for v1.

Notes — format and trust

Keep the existing URL format

cadernin-export://upload?projectId=…&… carries the project and optional score/songbook revision context as query parameters. Both protocol launches and pasted links use the existing parser.

A pasted link is protocol-launch input

One parser for both roads: parseExportDeepLink → validateExportContext against live Firestore, at panel resolve, again before the upload writes, and before any songbook re-pin. A paste never skips a check, never persists to disk, and the fallback card is only reachable signed-in — login comes first, exactly like today.
