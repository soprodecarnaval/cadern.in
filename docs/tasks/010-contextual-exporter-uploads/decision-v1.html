Task 010 · decision

After a songbook-scoped upload: silent re-pin, or ask first?

Both start the same way: the deep link named a project, a songbook and a score; the export app uploaded a new revision. The question is only what happens next to that songbook's pin.

A · Automatic today's 009 pattern

Pin updates the instant the upload finishes. Nothing to click.

⚠ If this link sat unused for two weeks and someone else already re-pinned or edited the songbook since, this silently overwrites that — the uploader never sees what they're changing.

B · Explicit recommended

Upload finishes; a confirmation names exactly what would change before it does.

Atualizar Mineirinho no caderninho Carnaval 2026 para a versão #4?
O caderninho está atualmente na versão #3. Esta ação cria uma nova revisão do caderninho.
ⓘEscolhendo "Agora não": a partitura já foi enviada: só o caderninho continua na versão antiga, atualizável depois em /manage.
✓ Catches a stale link cleanly: the uploader sees the songbook's current version before committing, every time.

Why this one leans explicit, unlike 009's thread copy

009's automatic choice was safe because it only ever adds an empty or copied comment thread — nothing existing is overwritten, and a wrong guess costs nothing. A re-pin instead replaces what every reader of that songbook currently sees, for a link that may be hours or weeks old by the time the export finishes (export + review + re-export is a slow loop). One confirmation click, scoped to the exact songbook and version named, removes that gap — and still never touches any other songbook pinning the same score.
